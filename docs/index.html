Go 1.27 · 零 Web 框架 · 零 ORM

把企业级 Go 服务的常用部分，一次性固化下来

matex 不做全家桶。它只固化最常用的布局与基础设施入口——标准库 net/http + 薄封装，配了才建、不配就不存在——再把这套约定交给 AI 与 skills 去生成代码。

一个部署单元，四行代码

服务 = Name() + Setup() + BuildRouter()。 verticle.Run 负责其余全部：加载配置、初始化基础设施、启动 HTTP、 处理信号、优雅退出。

go 
type Service interface {
    Name() string                              // 配置段 key、日志与指标前缀
    Setup(ctx context.Context, env *Env) error // 解码服务段、装配 domain
    BuildRouter(s *httpx.Server) error         // 注册路由
}

func main() {
    if err := verticle.Run(context.Background(), &app.DemoService{}); err != nil {
        log.Fatal(err)
    }
}

基础设施句柄对业务是私有的，一律经 Env 访问器读取：RequireDB() 在未配置时让启动失败，DB() 用逗号-ok 判可用。业务代码里不会出现 if env.DB != nil 这种话。

  • 业务代码不 import 驱动库 pgx、go-redis、franz-go、gin… 全部收在 pkg/core/* 之后， 由 golangci-lint 的 depguard 强制，不靠自觉。
  • Handler 不碰 ResponseWriter 签名统一 func(ctx, *http.Request) (any, error)：返回 nil 即 204，返回 errs.* 即对应状态码 + {code,msg,data}。
  • 配了才建，不配就不存在 只有 http: 段的最小配置也能起服务；db / redis / kafka / tracing / auth 随加随用，未配置时是 no-op，不为它们付任何代价。
  • 测试不需要 Docker 纯 Go SQLite、miniredis、kfake、进程内 gRPC·rpcx——make ci 跑的就是全部示例。

代码生成交给 AI，不交给 CLI

生成器是「会过时的约定」，skill 是「给 AI 的约定」。仓库里的 AGENTS.md 加一组 skill 就是生成器，而且随代码一起演进。

bash 
npx skills add smallnest/matex --all   # 一次装齐 15 个 skill

舍弃 理由
